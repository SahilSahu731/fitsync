# Explore content studio

Manage content from `/admin/mobility`, `/admin/learn`, and `/admin/tools`.
The admin sidebar links to all three editors. The existing admin role and
cookie-based web proxy protect writes; mobile users read published content only.

## Editing and publishing

Create a draft, add a cover URL or upload an image, then add content. Mobility
sessions have ordered movements, seconds, instructions, a movement illustration,
an easier option and optional demonstration video URL. The total duration is
calculated from the movement timers (including both sides). Articles have ordered
sections, illustrations, paragraphs and links. Use sections for takeaways and
next actions; related mobile resources use `/explore/resources/<slug>` links.

Preview shows the unsaved editorial content. Publish saves the entire record.
Unpublish & save draft removes it from published lists without deleting it.
There is no destructive content endpoint. If another tab saved a newer version,
the API rejects the stale edit and asks you to reload. Unsaved navigation prompts
protect drafts. Uploaded images use the existing server image-processing and
Cloudinary pipeline. Referenced images are never automatically deleted.

Tools select from 14 implemented calculators. Admins can edit the display title,
slug, summary, cover, explanation, worked example, ordering and publication state.
New mathematical operations require implementing and testing calculation logic
and adding the key to both server validation and mobile code. Preview displays
editorial content; test interactive calculations in the app.

## Data and seeding

The content studio works with the existing `009_explore_resources.sql` schema.
No new database table is required. Calculators share the resource store with
`kind=guide` and reserved `fitsync:tool` / `calculator:<key>` tags. The API maps
these rows to calculator records and excludes them from Learn and resource detail
routes. Admin article edits reject reserved tags, so content cannot accidentally
change category. `010_explore_content_studio.sql` adds an optional GIN index.

From `server/`:

```bash
npm run explore:seed-content
npm run explore:enrich-covers
npm run explore:check
```

The content seed adds 10 new mobility sessions, 10 new articles and 14 tools.
It uses `ON CONFLICT (slug) DO NOTHING`: existing content and subsequent admin
edits are preserved. The original starter seed now also ignores existing slugs.
The cover enrichment script only fills NULL covers on the 16 known starter slugs;
it does not change their text, rank, publication state or existing images.

Original vector movement diagrams live in `server/assets/explore/`. The seed
renders them to WebP and uploads them to Cloudinary. `media.json` caches their
public URLs so reruns reuse existing uploads. Photographic covers use fixed
Unsplash image URLs; these can be replaced through the editor. Diagrams are
instructional illustrations, not photos or validated biomechanical demonstrations.

`011_explore_curated_content.sql` is an alternative additive import containing the
same fully resolved media URLs. It is generated by the seed script. It is not
necessary to run it when the script already succeeded. Both import paths preserve
existing slugs. Deploy the server and mobile changes together so the reserved
calculator records are filtered consistently.

## Editorial references

Articles are original FitSync content, with practical examples distinguished
from general activity guidance. Source and related-session links appear in the
article detail screen.

## Verification

The live database was seeded: 18 mobility sessions, 18 articles and 14 tools.
The verification command checks minimum counts, representative original records,
calculator-key support, exclusion of tools from Learn, and cover image responses.
Server tests cover publication validation and tool storage round-trips; mobile
tests cover all calculator worked examples and invalid/boundary inputs.

Server build, web/mobile typechecks and lint of changed files pass. Full-repo lint
reports pre-existing errors in unrelated components. Production web builds were
attempted with both bundlers: Turbopack was blocked by worker socket permissions;
Webpack failed while parsing TypeScript CLI configuration output. Browser/native
visual QA and a full production app build remain unverified in this environment.
