# FitSync companion integration

This local Expo module is discovered automatically from `mobile/modules` during Android autolinking. It adds the **FitSync Today** home-screen widget without modifying generated native projects. A new Android development or release build is required; an existing binary or Expo Go cannot acquire the module through a Metro reload or OTA update. Older builds show an explicit unavailable state in the companion screen.

The widget receives a small account-scoped snapshot from the same program/plan and workout history used by the app. An active followed program takes priority over a coaching plan. It displays the sync date, periodically rerenders its cached snapshot, and replaces content older than 24 hours with an invitation to reopen FitSync. It does not fetch private data from a background receiver or contain authentication tokens. Snapshot writes are atomic and use Android's private no-backup directory. Logout/account replacement clears the previous snapshot. The system controls widget refresh timing and launcher pin support.

Personal reminders are implemented in `src/features/companion/reminders.ts` using the existing Expo Notifications dependency. Preferences are synced by the companion backend; notification delivery and permission are per phone. The app reconciles a rolling 14-day window on foreground, workout changes and plan changes. Scheduling uses the selected IANA timezone, ISO weekdays, quiet hours and exact completed plan/session references. Nonexistent daylight-saving times are skipped. Snooze respects quiet hours. Disabling reminders, completing their session, or switching accounts cancels this integration's notifications without cancelling program push or workout rest timers. When followed-program push reminders are enabled, personal notifications are paused to prevent duplicates; the settings screen explains the distinction.

Workout controls are actionable Android phone notifications. A compatible paired watch may mirror them when enabled in its companion app. Actions open the phone app to log the next fully populated set or pause/resume its rest timer. Set actions validate the current owner, session, set ID and required values, then use the existing workout persistence/sync path. Paused rest duration is stored per account and current session. This implementation does **not** include a standalone Wear OS app, watch-side input, or Apple Watch support.

Verification covers scheduling, quiet hours and DST, permission, cancellation, account isolation, stale notification actions and JS widget availability. XML resources and local Expo autolinking are checked separately. A physical Android/launcher/paired-watch pass and native build remain required before releasing this integration.
